# ADR-004: Redis como barramento interno no MVP, com porta para NATS

Data: 22/10/2026 · Status: aceito (revisado em 22/10/2026; a proposta original era NATS com JetStream)

## Contexto

O pipeline publica cada medição para regras e tempo real (Pipes and Filters e publicação e assinatura). O Redis já está na stack para último estado e deduplicação, e cada componente novo aumenta o risco de um projeto com uma pessoa e 40 dias.

## Decisão

Redis 8.8 (Streams para entrega com confirmação e pub/sub para tempo real) como barramento interno no MVP, atrás de uma porta de barramento no domínio. NATS com JetStream fica como adaptador alternativo, sem implementação no MVP.

## Consequências

Menos um serviço para operar e testar. Streams exigem gerenciar grupos de consumidores e mensagens pendentes à mão. Trocar por NATS exige só um adaptador novo, porque o domínio conhece apenas a porta.
