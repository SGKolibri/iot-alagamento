# ADR-009: Ferramentas de validação de contratos

Data: 22/10/2026 · Status: aceito

## Contexto

RNF-13 exige que o CI valide JSON Schema, AsyncAPI e OpenAPI, e RF-ING-06 vai usar o mesmo validador de mensagens na ingestão e no sandbox.

## Decisão

Ajv 8 com `ajv/dist/2020` e ajv-formats para o JSON Schema 2020-12, em modo estrito; `@asyncapi/parser` 3.6 para AsyncAPI 3.1; `@readme/openapi-parser` 10 para OpenAPI 3.1. Tudo fica em `packages/contracts`. Os schemas não declaram `$id` enquanto não houver URL pública, e o `$ref` do lote para a mensagem é relativo ao arquivo.

## Consequências

O mesmo pacote atende o CI, a ingestão e o validador do sandbox. Sem `$id`, os parsers resolvem as referências pelo sistema de arquivos e não tentam baixar uma URL que ainda não existe. Ao publicar os contratos por URL (RF-INT-01), o `$id` volta com o endereço real.
