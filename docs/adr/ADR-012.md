# ADR-012: ResultadoMensagem com indice e id_mensagem anulável

Data: 22/10/2026 · Status: aceito

## Contexto

No lote, uma mensagem recusada pode não trazer `id_mensagem` válido (campo ausente ou fora do formato UUID). O esquema `ResultadoMensagem` do OpenAPI exigia `id_mensagem` como UUID, e a T1a passou a devolver `null` nesses casos, fora do contrato (dívida da T1a).

## Decisão

`ResultadoMensagem` passa a ter `indice` (inteiro, base 0, obrigatório), a posição da mensagem no lote, e `id_mensagem` passa a aceitar `null`, mantendo o formato UUID quando houver valor. A resposta de `POST /ingestao` usa o mesmo esquema, com `indice` 0. Os exemplos de resposta entram em `docs/contracts/examples/responses/` e são validados contra o OpenAPI em `pnpm contracts:validate`.

## Consequências

O cliente casa cada resultado pela posição, mesmo sem id. A mudança é compatível porque a API ainda não foi publicada; a versão do OpenAPI sobe para 1.1.0, já que o campo novo é obrigatório na resposta e não quebra quem envia mensagens.
